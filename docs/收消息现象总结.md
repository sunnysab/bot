# 收消息问题 — 现象总结（2026-09-14）

## 背景

- 机器人：`/home/sunnysab/Code/bot`（Python，weixin-rs Python SDK 适配层 + 插件）。
- daemon：`/home/sunnysab/Code/weixin-rs`，`weixin-cli --daemon`（Mars longlink，TCP/UDS + MessagePack）。
- 账号：`雨墨蝉烟` / `wxid_6aob7w8khxa322`，`source = qr-manualauth`。
- 用户确认：**官方微信未登录**，不存在同号抢消息。

## 现象

1. **机器人收不到任何入站消息**：daemon `messages` 表始终为 0，bot 日志没有任何消息事件，群 @ / 私聊都一样。
2. **出站正常**：daemon 通过长链发出的消息，用户手机能收到。
3. 但 daemon 发送后报 500：`解析长链 newsendmsg 响应失败: invalid data: unsupported wiretype 7`。

## 已观测证据

### 长链本身是好的

- 启动日志：`长链完整握手建立，新 NST 已存档`（强制完整握手后）。
- 心跳：`Noop 心跳已发送` → `收到心跳 Ack cmdid=1000000006`。
- 发送：长链**明确收到响应帧** `收到消息发送响应 Ack cmdid=1000000237`。
  → 说明长链写、读、session 都正常。

### 但从来收不到 push

- `--log-level trace` 全程运行，**没有一条** `收到服务端同步通知`、也没有任何未知 cmdid 帧（`收到长链帧`）。
- 即：服务端根本不往这个 session 推 incoming。

### 入站短链 sync 一律空

- daemon RPC `sync`（`action_sync` → `/cgi-bin/micromsg-bin/mmsnssync`，report_arg 138）：
  `{new_messages:0, continue_flag:0}`。
- CLI `weixin-cli --sync`（`/cgi-bin/micromsg-bin/newsync`）：0.1s 返回、无 `[sync] ret=` 输出
  → 命中 `retcode = 0xfffffff3`(-13)，代码当作「游标已最新」静默返回。
- `--sync 3` 持续轮询同样一直 -13。

### 游标/会话材料不是原因

- `newinit` 成功，拿到新 `legacy_synckey`（78B），旧/新只差一个计数；之后仍无消息。
- `session_long.bin` 曾是 00:31 的旧文件、`session_short.bin` 是重登后的 01:17 新文件，
  daemon 优先加载旧的 long。移走后强制 `完整握手` 重生成 `session_long.bin`，**现象不变**。

### 发送 ACK 解析 bug（确定）

- 长链 `newsendmsg` 响应体是 **MmPacket**（首字节 `0xBF`；`0xBF & 7 == 7` → protobuf 报 wiretype 7）。
- `crates/weixin-cli/src/daemon.rs` `execute_newsendmsg` 长链分支**直接** `parse_newsendmsg_resp(&resp_frame.body)`，
  没有像短链分支那样 `parse_mm_header` + `AES-CBC(session_key)` + zlib 解包；
- 且解析失败 `?` 直接返回 500，**不会降级到可用短链**。
- 影响：消息实际已投递（用户能收到），但 `send_text` 对 bot 抛异常 → bot 回复循环中断（只发出第一行、不写历史）。

## 已排除

| 假设 | 结论 |
|---|---|
| bot 代码问题 | 排除（逻辑与 11 个单测通过） |
| 长链没连上 / 读循环坏了 | 排除（收得到心跳 Ack 与 NEWSEND_RESP） |
| `parse_newsync_resp` 没解包 | 排除（该函数有 parse_mm_header + AES + zlib） |
| 旧 `session_long` 材料 | 排除（完整握手重生成后现象不变） |
| 旧 `legacy_synckey` 游标 | 排除（newinit 重生后现象不变） |
| 官方客户端同号抢消息 | 排除（用户确认官方微信未登录） |
| daemon 收消息端点写错（mmsnssync vs newsync） | 未定论，但两条都 -13 |

## 当前判断

**微信不往这个 session 投递 incoming 消息，但允许它发送。**

收发走的是同一条长链、同一个 session：能收到发送回执，却收不到消息推送。
因此不是解析 / 游标 / 会话缓存的 bug，而更像**账号或登录方式被降权（可发不可收）**。
背景：该账号此前「登录被微信注销」，随后用 `--login qr` 重登；
`qr-manualauth` 登录很可能不是「可收 push 的在线设备」。
